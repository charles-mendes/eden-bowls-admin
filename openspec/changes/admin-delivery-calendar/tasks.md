# Tasks

Groups 1 to 7 are in `eden-bowls-backend`. Group 8 is in `eden-bowls-admin`. Group 9 checks both together.

Read endpoints come early. Every endpoint that writes the calendar or a sync (group 6, and the resend in group 7) comes after rescheduling (group 4) and audit (group 5), so no endpoint can close a day without moving the affected deliveries and recording the change.

Backend tests run one file at a time with `npx jest <file>` or `npm run test:related -- <file>`. Integration tests need `RUN_DB_INTEGRATION_TESTS=true`. Admin tests run with `npx vitest run --related <file>` and `npx playwright test <spec> --workers=4`. Do not run a whole suite after a small change.

It writes nothing. Verify with route tests for affected, locked, none affected, short notice at 6 and 7 days, and that no repository write or Stripe call happens.
- [ ] 4.3 Add the calendar write service (no route yet) for create, flag change, activate, deactivate, and remove. Validation: at least one flag set; no `national` creation or deletion; no `carrier` in `BR`; conflict error on a second row of the same type on a date. Writes that turn a flag on (create, activate, flag on) run in one MySQL transaction: write the row, project again, refuse with an error naming the locked subscriptions if any is locked, otherwise update stored preparation and delivery dates where present and insert one pending sync per moved subscription with a stored `trial_end` (target 00:00 of the new preparation day in the market timezone). Verify with unit tests for each validation rule, move, locked refusal, delivery locked after the preview, and Stripe unavailable (save succeeds, syncs pending).
- [ ] 4.4 Check that deactivate, delete, and flag-off writes leave stored dates, `trial_end`, and sync rows unchanged. Verify with unit tests of the write service.
